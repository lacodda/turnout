A developer's switchyard. Your local apps keep talking to localhost; turnout points them at whichever backend stand you pick, keeps the servers and secrets that reach those stands, and builds and deploys - from any directory.

<CardGrid>
	<Card title="Switch stands, stay signed in" icon="link">
		`turnout use web staging` - and `http://web.localhost` reaches staging, with a session kept per app and stand. [Gateway](/turnout/concepts/gateway/)
	</Card>
	<Card title="Work from any directory" icon="setting">
		`dev`, `build` and `test` run in the project's folder, quiet until something breaks, or in the background. [Jobs](/turnout/concepts/background-jobs/)
	</Card>
	<Card title="Deploy, and trust it" icon="rocket">
		To Linux and Windows servers: a backup first, a health check after, a rollback when it fails. [deploy](/turnout/reference/deploy/)
	</Card>
	<Card title="Access in one place" icon="seti:lock">
		The OS keyring, keys set up and proven, the SSH agent, every host key checked. [SSH access](/turnout/guides/ssh-access/)
	</Card>
</CardGrid>

```bash
brew install lacodda/tap/turnout      # or: scoop install turnout · npm i -g turnout-cli · cargo install turnout
```

**1.0** means the settings are a contract: an export from any release since 0.11 imports, and nothing in 1.x breaks it.
