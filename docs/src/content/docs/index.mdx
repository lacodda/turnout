## A day in the life

```console
$ turnout use web staging
'web' now uses 'staging'.
The running gateway picks this up automatically.
Stand check: https://staging.example.com responded with 200 OK.

$ cd ~/dev/web/src/components
$ turnout dev
[web] pnpm dev
```

Nothing in the project changed - the app still talks to `localhost`, and the [gateway](/turnout/concepts/gateway/) routes it to the stand you picked. Cookies are kept per app **and** stand, so the switch does not log you out.

## What turnout does

<CardGrid stagger>
	<Card title="Dev gateway" icon="rocket">
		Your apps always talk to localhost; turnout routes requests to the selected stand. Switching is one command, and sessions survive it - the gateway keeps a cookie jar per app+server pair.
	</Card>
	<Card title="Secrets in the OS keyring" icon="seti:lock">
		Windows Credential Manager, macOS Keychain or Linux Secret Service. Copy a password to the clipboard with one command; nothing lives in plain files.
	</Card>
	<Card title="Commands from anywhere" icon="setting">
		dev, build, test and lint run in the right project folder for you - no cd required. Commands come from your actual package.json scripts.
	</Card>
	<Card title="Deploy" icon="cloud-download">
		Build, upload over SSH/SFTP, restart the service - with remote backup and restore when a release goes wrong.
	</Card>
	<Card title="Nothing to memorize" icon="approve-check">
		Leave a name out and pick it from a list; in bash, Tab completes app, server and group names from your own catalogs.
	</Card>
	<Card title="An action journal" icon="document">
		Every state change appends one JSON line - what happened and to which entities, never secrets. tail, grep and jq work on it directly.
	</Card>
</CardGrid>
